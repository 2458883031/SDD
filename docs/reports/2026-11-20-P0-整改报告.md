## 二、整改内容

### 2.1 补齐三篇架构文档

#### ✅ `docs/architecture/platform-architecture.md`（新增）

**内容：**
- 平台适配层职责定义
- Codex、Claude Code、Cursor、OpenClaw、Gemini CLI、OpenCode 六大平台能力分析
- 兼容性矩阵（9 个维度）

- 验证方法

**关键决策：**
- 不宣称完全兼容，明确标注支持程度
- 分级适配：预期原生支持 / 预期通过适配支持 / 预期部分支持 / 预期不支持 / 尚未评估（均未实测）

#### ✅ `docs/architecture/security-architecture.md`（新增）

**内容：**
- Agent 权限分级模型（R0–R4，避免与项目阶段 P0–P7 混淆）
- Skill 执行安全（输入验证、输出过滤、危险操作清单）
- 工具调用权限白名单
- 文件系统访问边界（项目沙箱）
- Shell 命令执行限制（超时、并发、审计日志）
- 凭证和敏感信息管理
- 人工审批机制（触发条件、不可跳过规则）
- 高风险操作审计和回滚
- 多 Agent 信任边界

**关键决策：**
- 生产环境变更必须 G6 人工审批
- 安全敏感操作（认证、授权、加密）必须人工确认
- 所有 exec 调用记录审计日志

#### ✅ `docs/architecture/testing-architecture.md`（新增）

**内容：**
- 测试层级设计（T1–T4，避免与系统架构层 L1–L6 混淆）
- Skill 单元测试（范围、用例设计、执行、验收标准）
- Workflow 集成测试（范围、用例设计、端到端测试）
- Agent 端到端测试（场景库、执行方式）
- 平台兼容性测试（测试矩阵、平台特定测试）
- 安全测试（测试清单、执行）
- 回归测试（策略、套件）
- 验收标准表
- 测试基础设施（目录结构、工具）

**关键决策：**
- 分层测试策略，从单元到端到端
- 每个 Skill 必须通过触发、输入、输出、边界测试
- 工作流必须验证产物传递和门禁触发
