## 二、F3-1：Input Schema

`skills/design/schemas/input.schema.json`：

- 从顶层 `required` 中移除 `requirements_ref`、`analysis_ref`、`complexity`；
- 保留字段存在时的全部约束：
  - `requirements_ref` 必须是 type=requirements 的 ArtifactRef；
  - `analysis_ref` 必须是 type=analysis 的 ArtifactRef；
  - `complexity` 只能是 L1/L2/L3；
  - `additionalProperties: false`，未知字段仍拒绝；
  - 其他可选字段规则不变。
- 未放宽 ArtifactRef 内部 path/version/sha256/type 约束。
- 增加 schema 描述，说明这三个字段是 Skill 契约要求，但故意交给 Skill 状态逻辑处理缺失情况。

`{}` 在纯 JSON Schema 结构校验下现在是合法对象；这不表示 Design 可以执行，而是让 Skill 有机会按契约返回 `needs_input`/`blocked`，而不是在 Schema 阶段统一变成 `input_invalid`。

## 三、F3-2：Skill 状态分支与优先级

`SKILL.md` 与 `docs/standards/design-standard.md §3` 已明确执行顺序：

1. **Schema 检查存在的字段**：
   - 类型错误、Artifact type 错误、SHA 格式错误、非法 enum、未知字段 → `failed` + `input_invalid`；
   - 缺失字段不被 Schema 顶层 `required` 提前拒绝。
2. **缺失上游引用**：
   - 缺 `requirements_ref` 或 `analysis_ref` → `needs_input`；
   - `questions` 至少一项，并列出所有缺失引用；
   - 此项优先于缺失 `complexity`。
3. **缺失 Orchestration complexity**：
   - 引用齐全但 `complexity` 缺失 → `blocked` + `precondition_failed`；
   - Design 不自行推断或降低复杂度。
4. **字段有效后**：
   - 才执行 Artifact 读取、路径和身份验证；
   - 路径/任务目录/符号链接/内容 SHA 仍由调用层或语义校验完成（F4 已明确）。

### 多字段缺失优先级

| 缺失情况 | 结果 |
|----------|------|
| 缺 requirements_ref 和/或 analysis_ref（无论 complexity 是否存在） | `needs_input`，questions 列出缺失引用 |
| 引用齐全，缺 complexity | `blocked` / `precondition_failed` |
| 字段存在但类型/枚举/Artifact type 错误 | `failed` / `input_invalid` |
| 全部存在且有效 | 继续 Artifact 读取和设计流程 |

该优先级稳定且可测试；缺失引用不会被错误归类为不可恢复的 `failed`。

## 四、F3-3：Output Schema 核对

现有 Output Schema 已足够表达状态结果，因此未修改：

- `needs_input`：`data.questions` 至少一项，允许无 design Artifact；
- `blocked`：`data.blocked_reason` 非空，允许无 design Artifact；
- `failed`：`errors` 至少一项；
- 非 `ok` 状态不强制 design Artifact，不伪造部分设计；
- `ok` 仍要求至少一个 `type=design` Artifact。

实际输出结构测试：

```text
needs_input: PASS
blocked: PASS
failed: PASS
```

## 五、F3-4：针对性测试

使用实际 Input Schema 和 `jsonschema` Draft 2020-12，并配合一个明确标记为 **contract decision fixture** 的状态判定函数（不是 Runtime）：

```text
valid: PASS schema=accepted decision=proceed
missing-requirements-ref: PASS schema=accepted decision=needs_input
missing-analysis-ref: PASS schema=accepted decision=needs_input
missing-complexity: PASS schema=accepted decision=blocked/precondition_failed
missing-all-three: PASS schema=accepted decision=needs_input
invalid-complexity: PASS schema=rejected decision=failed/input_invalid
invalid-requirements-type: PASS schema=rejected decision=failed/input_invalid
invalid-analysis-type: PASS schema=rejected decision=failed/input_invalid
```

说明：

- missing-* 场景证明 Schema 不再提前拒绝，状态分支可发生；
- invalid-* 场景证明字段存在时 Schema 仍拒绝非法类型/枚举；
- missing-all-three 证明稳定优先级：缺失引用 → `needs_input`，不是 `blocked` 或 `failed`；
- 这是契约测试，不是 Design Runtime、不是 Skill 执行器。
