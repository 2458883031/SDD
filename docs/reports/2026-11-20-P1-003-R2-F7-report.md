## 二、语法定义

### 2.1 裸 SHA-256

```text
^[a-f0-9]{64}(?![\s\S])
```

- 恰好 64 位小写十六进制；
- 必须为绝对字符串结束；
- 不接受前后缀、LF、CR、空格、Tab 或任何额外字符。

### 2.2 版本化引用

```text
^(?!.*(?:^|/)\.\.?(?:/|@))
 (?!(?:.*[a-f0-9]{64}){2})
 (?:[A-Za-z0-9._-]+/)*[A-Za-z0-9._-]+
 @(?:0|[1-9][0-9]*)
 #(?P<sha>[a-f0-9]{64})
 (?![\s\S])
```

（实际实现为单行；上图为可读换行。）

格式：`path@version#sha256`。

### 2.3 path 规则

- 非空、仓库相对路径；
- 每段仅允许 ASCII 字母、数字、`.`、`_`、`-`；
- 段之间恰好一个 `/`；
- 禁止空段（`//`）、前导 `/`、尾随 `/`；
- 禁止 `.` 或 `..` 段；
- 禁止未转义的 `@` 或 `#`。

### 2.4 version 规则

- 十进制非负整数：`0` 或 `[1-9][0-9]*`；
- 禁止前导零（`01` 无效）；
- 禁止符号、空版本或非数字字符。

### 2.5 SHA-256 与末尾约束

- 64 位小写十六进制；
- 整个引用中恰好一个 64 位小写十六进制摘要；
- 位于引用绝对末尾；
- 摘要后不得有 LF、CR、空格、Tab 或任何额外字符。

### 2.6 明确拒绝的形式

- `path#sha256`（无 `@version`）；
- `docs/evidence.md#extra@1#<sha>`（路径额外 `#`）；
- `docs/evidence@extra.md@1#<sha>`（路径额外 `@`）；
- `@1#<sha>`（空路径）；
- `docs/evidence/@1#<sha>`（尾随 `/`）；
- `/docs/evidence.md@1#<sha>`、`docs//evidence.md@1#<sha>`；
- `docs/./evidence.md@1#<sha>`、`docs/../evidence.md@1#<sha>`；
- `docs/evidence.md@01#<sha>`、`@#<sha>`、`@+1#<sha>`；
- 合法引用后追加 LF/CR/空格/Tab；
- SHA 前或后追加额外字符；
- 路径内第二个 64 位摘要、重复摘要、多个摘要、缺失摘要；
- 大写或混合大小写摘要；
- 非字符串输入。

所有不符合规范的引用一律 fail-closed。

## 三、代码整改

### 3.1 Python 解析器

`tests/unit/analysis/validate_analysis_skill.py`：

- `artifact_sha()` 只接受完整规范结构；
- 裸 SHA 使用 `[a-f0-9]{64}` + `fullmatch()`；
- 版本化引用使用 `VERSIONED_REF_RE.fullmatch(ref)`；
- 完整结构通过后，从已验证的命名捕获组 `sha` 提取摘要；
- 不使用无锚点 `search()`；
- 不在验证前使用 `rsplit()`；
- 非字符串返回 `None`；
- 解析失败不进入 `resolved_evidence_exists()` 成功路径。

版本化 pattern 中的负向前瞻同时拒绝：

- `.` / `..` 路径段；
- 全文第二个 64 位摘要。

### 3.2 JSON Schema

`skills/analysis/schemas/output.schema.json`：

- `resolution_evidence_refs.items` 使用 `oneOf`，只允许裸 SHA 或严格版本化引用；
- 裸 SHA pattern 使用 `(?![\s\S])` 绝对结束，不依赖 `$`；
- 版本化 pattern 与 Python 使用同一 path 字符集合、同一 version 规则、同一单摘要负向前瞻和同一绝对结束；
- 额外 `#`/`@`、空/前导/尾随 slash、`.`/`..` 段、前导零版本、多摘要、大小写混用、末尾 LF/CR/空格/Tab 均不能通过；
- 同时将 `artifactRef.sha256` 与 evidence `sha256` 的 pattern 收紧为绝对结束，避免同类末尾换行漏洞。

### 3.3 Schema 与解析器一致性

测试直接读取实际 `output.schema.json` 的 `$defs.traceItem.properties.resolution_evidence_refs.items` 构造 `Draft202012Validator`，对共享向量逐项比较：

```text
Schema accepts == (artifact_sha(ref) is not None)
```

共享向量共 **30** 个，全部 **30/30** 一致。覆盖合法裸 SHA、合法版本化引用、多段路径、隐藏文件、空/前导/尾随 slash、`.`/`..` 段、额外分隔符、前导零/空/带符号版本、末尾 LF/CR/空格/Tab、SHA 前后额外字符、多摘要、缺失摘要、大小写混用和非字符串。

### 3.4 Requirements SHA 身份比较

- `is_requirements_ref()` 仍以规范解析出的 SHA-256 判定；
- 合法 Requirements path、`path@version#sha256`、裸 SHA 均识别为同一 Requirements Artifact；
- 同一 SHA 更换 path（如 `other/path/requirements-copy.md@7#<req-sha>`）仍识别为同一 Artifact；
- 非规范引用无法解析，不会成为独立解决证据。
