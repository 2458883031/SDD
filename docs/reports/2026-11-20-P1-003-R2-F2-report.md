## 二、Disposition 语义规则

| disposition | 规则 |
|-------------|------|
| `analyzed` | 必须有非空 `analysis_refs`，且每个 ref 可解析到候选方案/风险/设计考虑/技术上下文/问题陈述/可行性/比较维度；仅标签不允许 |
| `mapped` | 保留原规则；`analysis_refs` 必须指向真实 candidate/risk/design；不得任意字符串 |
| `retained` | 必须闭环到实际 Analysis 输出：Unknown→`analysis.unknowns`；Assumption→`analysis.assumptions`；Non-goal→`problem_statement.non_goals`；Open Question→`next_steps` 对应问题；Constraint/Dependency/Acceptance/FR/NFR/SourceRef→对应上下文或分析结果 |
| `resolved` | 必须有非空 `resolution_evidence_refs`，且每个 ref 可追溯到事实证据/分析证据/候选/风险证据 |
| `not_applicable` / `deferred` | 必须有非空 `rationale`；不得作为静默删除上游内容的通道 |

`analysis_refs` 支持可验证前缀：

- `solution:<id>`、`risk:<id>`、`design:<text>`；
- `technical:<field>`、`problem:<field>`、`feasibility:<area>`、`comparison:<dimension>`；
- 兼容旧写法（直接 solution_id/risk_id/design consideration）。
