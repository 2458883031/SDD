### 2.1 示例修正

OpenClaw 初稿存在条件性设计声明与内容不一致，已修正：

- L1/coverage/deviation 声称设计了 interfaces，但没有 `interfaces` 字段；已补充真实接口设计；
- L1/coverage 的 designed coverage 使用空字符串 rationale；已移除占位空字符串；
- L2 有性能 NFR 但缺 `performance_scalability`；已补充；
- L2 coverage 将已有数据模型错误标为 N/A；已改为 designed 并指向 DM-1；
- coverage 示例曾将安全设计 Deferred 到 G2；已改为有理由的 N/A（无新增信任边界），性能 Deferred 保留原因/影响/后续条件。

## 九、发现的问题与修正

OpenClaw 初稿完成后，Claude Code 独立复核修正：

1. 示例中条件性区域声明与实际字段不一致（interfaces 声明但无 `interfaces`；性能 NFR 但无 `performance_scalability`）；已补齐并修正 coverage。
2. L1/coverage designed coverage 的空 rationale 占位已移除。
3. coverage 示例将安全设计 Deferred 到 G2，违反“不得通过 Deferred 逃避必要安全设计”；改为有理由的 N/A（无新增信任边界）。
4. invalid cases 001–003 被错误标为 schema-input；F3-Final 已移除 Input Schema required，缺失字段实际应走 contract-status；已重新分层。
5. invalid cases 019–021、024 属于 schema-output（additionalProperties），但被标为 semantic；已重新分层并实际执行。
6. 负向 Case 026 重复，已改为 `gate_approved`；新增 027 Approval、028 Deferred 后续条件、029 fake G2。
7. `DESIGN-INVALID-015` 的 Deferred rationale mutation 索引错误；已改到 performance deferred 项。
8. Cases 验证器原先按文件名/重复计数、未执行 contract-input-status；已重写为按 fixture 语义统计，区分 schema 与 semantic。
9. `tests/unit/design/requirements.txt` 错误写成 Skill 依赖格式；已改为 `jsonschema` / `PyYAML`。
10. Checklist 相对链接深度错误；已修正为 `../../../docs/standards/...`。
