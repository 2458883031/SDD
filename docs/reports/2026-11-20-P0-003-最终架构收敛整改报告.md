### P0-003-02 R0–R4 权限模型统一

**修改文件：** `docs/architecture/security-architecture.md`

**统一后的权限口径：**

| 权限 | 定义 | 示例 |
|------|------|------|
| R0 | 只读 | 读取允许访问的项目文件 |
| R1 | 普通写入 | 修改项目文件、生成文档 |
| R2 | 受控执行 | 运行测试、构建、受限脚本 |
| R3 | 高风险操作 | 部署、数据库迁移、外部网络写操作、非生产环境管理 |
| R4 | 严重敏感操作 | 生产数据破坏性操作、敏感凭证读取、不可逆高危操作 |

**明确约束：**

1. 生产部署 = **R3 + G6 + SA**（SA：显式人工授权）。
2. 生产数据库破坏性操作 = **R4 + SA**；涉及部署时加 G6。
3. 敏感凭证读取 = **R4 + SA**。
4. 高风险 Shell 按影响范围定为 R2/R3/R4。
5. 权限与审批分离；G6 是质量与发布门禁，不是权限检查。
6. SA 是显式人工授权，不得被自动化检查或 Agent 自行批准替代。
7. 默认拒绝未声明的权限。
8. 不得通过降低任务复杂度、拆分任务或新建会话绕过权限要求。

**验证：** 扫描确认无旧标签（`R1-编辑`、`R2-执行`、`R3-管理`、`R4-危险`）；生产部署/数据库/凭证/高风险 Shell 的映射一致。

### P0-003-03 Task Context 状态机

**修改文件：** `docs/decisions/ADR-005-task-context.md`、`docs/architecture/orchestration-architecture.md`

**正常流程：**

```text
created → planned → executing → verifying → completed
```

**审批流程：**

```text
executing → awaiting_approval
  ├── approved → executing（恢复原 current-stage）
  ├── rejected → aborted
  └── timeout  → aborted（approval_timeout）
```

**异常流程：**

```text
executing / verifying → failed / aborted
```

**新增规则：**

- 不需要审批的任务允许 `executing → verifying` 直接转换；只有触发审批条件的任务进入 `awaiting_approval`。
- 审批通过恢复原 `current-stage`，不丢 Task Context 或 Artifact 引用。
- 审批拒绝 → `aborted`；审批超时 → `aborted`（`approval_timeout`），超时不等于批准。
- `failed` = 执行已尝试但不可恢复；`aborted` = 主动终止/拒绝/策略停止。
- 重试必须保留原任务与 Artifact 历史；重试使用新 `task-id`，通过 `parent-task-id` 指向原任务。
- `completed/failed/aborted` 为终止状态，禁止直接恢复；重新执行需新任务或新重试实例。
- 新增 `parent-task-id` 字段；orchestration-architecture.md §6 引用状态机权威定义。
