## 二、F5-A：统一 Artifact 身份识别

### 2.1 规则

Resolved evidence 的 Artifact 身份以 **SHA-256** 为准，不以 path 字符串为准：

1. `artifact_sha(ref)` 从引用中提取 64 位 SHA-256（支持裸 sha、`path@version#sha`、`path#sha`）。
2. `resolution_evidence_refs` 必须包含不可变 SHA-256；纯 path、普通 source_refs 登记不再接受。
3. `is_requirements_ref()` 同时检查：
   - 原始 Requirements path；
   - 原始 `path@version#sha256`；
   - 裸 sha256；
   - 任意包含相同 SHA-256 的引用（不同 path/目录/文件名）。
4. 相同 SHA-256 的不同 path 仍是同一 Artifact，不能当作独立证据。
5. 普通 source_refs 未重新加入 resolved evidence 集合。
6. Schema `resolution_evidence_refs` items 增加 `[a-f0-9]{64}` pattern，强制不可变 SHA-256。

### 2.2 负向测试（9 个场景）

1. 原始 Requirements path：拒绝；
2. 原始 `path@version#sha256`：拒绝；
3. 裸 SHA-256：拒绝；
4. 相同 SHA-256、相同 version、不同 path：拒绝；
5. 相同 SHA-256、不同目录及文件名：拒绝；
6. 相同 Artifact 的其他规范化引用形式：拒绝；
7. 更换 path 后同时出现在 `facts.evidence_refs`：拒绝；
8. 更换 path 后同时出现在 `candidate_solutions.evidence_refs`：拒绝；
9. 更换 path 后同时出现在 `risk_assessment.evidence_refs`：拒绝。

`resolved_negative=15`（含既有 6 个证据语义负向 + 本轮 9 个场景）。

### 2.3 正向测试（3 个）

独立证据均使用不同于 Requirements Artifact 的 SHA-256：

1. `facts.evidence_refs` 中的独立引用：通过；
2. `candidate_solutions.evidence_refs` 中的独立引用：通过；
3. `risk_assessment.evidence_refs` 中的独立引用：通过。

`resolved_positive=3`。
