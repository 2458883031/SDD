## 三、Analysis 契约

### 3.1 输入

- `requirements_ref`（必需）：Requirements Artifact（path/version/sha256/type=requirements）。
- `requirements`（可选）：R1 `data.requirements`；由 `skills/requirements-clarity/schemas/output.schema.json` 校验，不复制第二套 Requirements Schema。
- `project_context`、`technical_context`、`constraints`、`existing_analysis`、`evidence_refs`、`change_context`、`requested_scope`。

输入状态：

- 缺失/结构无效 → `failed`/`input_invalid`；
- 上游 blocking 未决项/冲突 → `needs_input`/`blocked`；
- 引用不一致 → `blocked`；
- 不得仅凭字段存在认定输入有效。

### 3.2 输出

统一 Envelope：`status/data/artifacts/errors/evidence`；`data.analysis` 包含：

- `analysis_id`、`analysis_version`；
- `source_requirements_ref`、`source_requirements_version`、`source_refs`；
- `problem_statement`；
- `technical_context`；
- `candidate_solutions`；
- `feasibility_assessment`；
- `risk_assessment`；
- `comparison_matrix`；
- `recommendation`；
- `facts`、`assumptions`、`unknowns`；
- `next_steps`；
- `single_solution_rationale`（单候选时必需）。

禁止字段：`implementation_plan`、`design_spec`、`design_approved`、`gate_approved`、`confirmation_ref`。

### 3.3 候选方案

每个候选包含：

- `solution_id/name/description/approach`；
- `applicable_requirements`、`prerequisites`、`advantages`、`disadvantages`；
- `technical_complexity`；
- `implementation_cost_estimate`、`operational_cost_estimate`（estimate/basis/confidence）；
- 性能/安全/维护/扩展/迁移/兼容影响；
- `dependencies`、`risks`、`evidence_refs`、`assumptions`、`unknowns`。

规则：

- 不机械要求三个方案；
- 单方案必须有 `single_solution_rationale`，解释其他方案为何不适用/不可行；
- 不得编造候选；
- 成本/性能/复杂度估计必须说明依据和置信度。

### 3.4 可行性与风险

可行性覆盖 technical/resource/compatibility/performance/security/operations/data_migration/external_dependencies/delivery；每项含 assessment/status/evidence/assumptions/unknowns/rationale。

风险含 risk_id/description/category/likelihood/impact/severity/severity_basis/mitigation/residual_risk/evidence/status；不得把风险等级伪装成量化评估。

### 3.5 比较与推荐

比较矩阵含 method/weighted/weight_basis/dimensions/comparison_summary；评分含 solution_id/score/not_applicable/basis/confidence。加权时必须有 method、weight_basis、每维 weight，权重和约 1。

推荐含 recommended_solution_id/rationale/trade_offs/unresolved_risks/conditions/confidence/recommendation_status。推荐不等于 Design 批准；recommended_solution_id 必须存在；未解决风险必须存在。

### 3.6 状态和完成

- `needs_input`：输入不足/需澄清；
- `blocked`：上游阻塞/冲突；
- `needs_approval`：需要 G/SA 建议；
- `failed`：执行失败；
- `ok`：分析完成且无 blocking 未决项；**不代表 Design 已批准、G2 通过或用户确认**。

`ok` 不得含 blocking unknown/open question、未解决冲突或 next_steps.blocking_questions；可含非阻塞问题。

### 3.7 Artifact 与版本

- Analysis 输出是独立 `type=analysis` Artifact；
- `source_requirements_ref` 引用 Requirements Artifact；
- 记录 source version/hash；
- Requirements 变化时提示重新评估，但不实现自动失效；
- ADR-009 Proposed 的 G1/G2/G3 binding 仍为提案，不实现 GateDecision/Approval Runtime；
- 不创建新 Artifact 类型体系。
