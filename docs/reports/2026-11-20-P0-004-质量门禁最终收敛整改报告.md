## 三、逐项整改情况

### P0-004-01 修正 Bug Fix 工作流

**修改文件：** `docs/decisions/ADR-006-quality-gates.md`

**修改后：**

```text
Analysis
   ↓
Coding
   ↓
 ┌─────────────┐
 │             │
Review (G4)  Testing (G5)
 │             │
 └──────┬──────┘
        ↓
   G4 AND G5
        ↓
    Completed
```

- Review 与 Testing 是独立质量活动，允许并行，但 G4、G5 必须全部通过。
- Review 失败/严重问题返回 Coding；修复后必须重新执行 Review。
- Testing 失败返回 Coding；修复后必须重新执行相关测试。
- Testing、Lint、Typecheck 不能替代独立 Code Review。
- 简单修改 Workflow 的既有规则不变。

**同步修改：** ADR-006 §9 任务表 Bug Fix 行、§10 门禁关系说明。

### P0-004-02 修正 G6 触发条件

**修改文件：** `docs/decisions/ADR-006-quality-gates.md`

**统一规则：**

- G6 是**生产部署授权门禁**，只在生产部署动作发生之前触发。
- G6 不能被 G4/G5 替代，不能替代 R3/R4 操作权限检查，不能替代 SA 显式人工授权。
- 不涉及生产部署的任务不得被强制要求通过 G6。
- 非生产环境部署的安全限制由 R0–R4 权限模型负责。
- 生产部署授权必须在实际部署动作之前完成；部署后验证属于 Deployment Verification。

**新增 G6 适用性表：**

| 任务类型 | G6 要求 |
|----------|---------|
| 仅代码开发和交付，不涉及生产部署 | **N/A** |
| 新项目开发，但不涉及生产部署 | **N/A** |
| 新项目开发，且计划生产部署 | 生产部署动作前必须通过 G6 |
| 非生产环境部署 | **N/A**，按 R0–R4 权限模型执行 |
| 生产部署 | 必须通过 G6 + R3 + SA |
| 生产数据库破坏性操作 | R4 + SA，并执行适用的独立安全控制；涉及生产部署时再加 G6 |

**同步修改：**

- §8 G6 增加“不适用”范围。
- §9 任务表：简单修改、Bug 修复、功能开发、系统重构的“G6 如部署”全部改为“G6 仅生产部署”。
- §9 新项目行改为 `G1–G5；G6 仅计划生产部署`，不再强制 G6。
- §9 部署任务行区分非生产/生产：非生产按 R0–R4，不触发 G6；生产部署 G6 + R3 + SA。
- §10 图中的 `G6 Deployment` 标注“仅生产部署”。
- 新增“部署任务复杂度示例”（L1 非生产 N/A；L2 生产 G6 + R3 + SA；L3 生产 + 迁移/破坏性 G6 + R3/R4 + SA + 安全审查）。
