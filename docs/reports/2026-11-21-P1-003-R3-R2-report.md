### 2.2 Skill 职责与执行

`SKILL.md` 已将 Design Standard 转化为面向 Agent 的操作指令：

- 读取 Requirements/Analysis Artifact，校验 type/version/sha256；
- 校验 Orchestration 提供的 L1/L2/L3 complexity；
- 建立 Requirements 与 Analysis 追踪；
- 按复杂度裁剪设计区域；
- 记录 Key/Lightweight Decision、备选方案和偏离推荐理由；
- 构造 `type=design` Artifact；
- 处理 `ok/needs_input/needs_approval/blocked/failed`；
- 明确 `ok` 不等于 G2；`needs_approval` 不等于 G2；
- 禁止 implementation_plan、任务拆解、排期、assignments、GateDecision、Approval、`design_approved`、`gate_approved`、`confirmation_ref`；
- 不执行 Shell/数据库/部署/生产操作；
- `runtime_behavior = NOT_EXECUTED`。

### 2.3 Artifact Contract

- Design 输出 `type=design`，复用 ADR-005 path/version/sha256。
- `source_requirements_ref` 必须是 type=requirements；`source_analysis_ref` 必须是 type=analysis。
- `design_version` 使用 SemVer；Artifact `version` 是 ADR-005 整数版本，两者不混用。
- `ok` 至少一个 design Artifact。
- 不新增 Artifact 类型、Gate、Approval、Evidence 或状态机。

## 三、Schema 验证

### 3.1 Input Schema

`skills/design/schemas/input.schema.json`：

- Required：`requirements_ref`（type=requirements）、`analysis_ref`（type=analysis）、`complexity`（L1/L2/L3）。
- Optional：`task_context`、`requirements`、`analysis`、`project_context`、`technical_context`、`constraints`、`existing_design`、`user_clarifications`、`change_context`、`requested_scope`、`evidence_refs`。
- ArtifactRef 使用 path/version/sha256/type，SHA 为 64 位小写十六进制。
- `requirements_ref`/`analysis_ref` 使用类型 const 的 artifactRef 子类型；缺少 type 或类型错误由 Schema 拒绝。
- 不接受隐式 latest；不复制 Requirements/Analysis Schema。

### 3.2 Output Schema

`skills/design/schemas/output.schema.json`：

- 严格使用 P1-001 五字段 Envelope：`status/data/artifacts/errors/evidence`。
- 未添加任务书建议但权威 IO 契约不存在的 `skill_id`、`skill_version`、`warnings` 或单数 `artifact`。
- 五状态条件：
  - `ok`：完整 `data.design`、至少一个 type=design Artifact、errors 为空；
  - `needs_input`：`questions` 至少一项，可带部分 design；
  - `needs_approval`：`approval_request`（gate_or_sa/reason/impact/rollback），`gate_or_sa` 不得为 `G2`，不产生 GateDecision/Approval；
  - `blocked`：`blocked_reason`，可带部分 design；
  - `failed`：至少一个 error。
- `data.design` Required：design identity、design_version、created_at、source refs、complexity、summary、decisions、architecture_overview、test_strategy、requirements/analysis traceability、risks、assumptions、unknowns、open_questions。
- Conditional/Optional：selected_solution、alternatives、components/modules、interfaces、data_models/data_flows、state_model、failure_handling、security_design、performance_scalability、migration_rollback、design_change_impact、implementation_constraints、coverage、source_refs。
- Coverage 支持 `designed/not_applicable/deferred`；N/A/deferred 必须给理由；designed 必须有 design_refs。
- Requirements traceability 支持 designed/mapped/retained/resolved/N/A/deferred；Analysis traceability 支持 adopted/adapted/rejected/retained/N/A/deferred；条件字段有对应必填项。
- 解析证据沿用严格 SHA-256 引用规则（裸 SHA 或 path@version#sha256，单摘要、绝对末尾）。
- Key Decision 必须有 alternatives/consequences/related requirements；Lightweight Decision 可简化。
- 禁止字段无法通过 `additionalProperties:false` 注入：implementation_plan、design_approved、gate_approved、confirmation_ref、gate_decision、approval 等。

### 3.3 Schema 正/负向检查

使用实际 `input.schema.json` 和 `output.schema.json`，通过 `jsonschema` Draft 2020-12 进行最小结构测试：

- 最小合法 Input：PASS；
- 最小合法 `ok` Output：PASS；
- `needs_input` / `needs_approval` / `blocked` / `failed` 最小结构：PASS；
- Input 负向：
  - requirements_ref type 错误：拒绝；
  - analysis_ref type 错误：拒绝；
  - 缺 analysis_ref：拒绝；
  - complexity 非法：拒绝；
- Output 负向：
  - implementation_plan：拒绝；
  - decisions 为空：拒绝；
  - Key Decision 缺 alternatives/consequences/related requirements：拒绝；
  - Requirements traceability 为空：拒绝；
  - N/A disposition 无 rationale：拒绝；
  - Artifact type 不是 design：拒绝；
  - ok 无 Artifact：拒绝；
  - test_strategy 缺 acceptance mapping：拒绝；
  - `gate_or_sa=G2`：拒绝。
- 额外结构检查：source refs 类型错误、非法 SHA 证据、空 design_refs、空 architecture、coverage N/A 无理由、`终态` 旧字段均拒绝。

**限制：** Schema 只验证结构、类型、枚举、必填与可表达的 JSON Schema 条件；不验证 Requirements/Analysis 内容一致性、追溯完整性、决策真实性、设计质量、Artifact 内容哈希或 G2 语义。后者属于后续 Semantic Validator/Orchestration，R2 未实现。

## 六、发现的问题与处理

OpenClaw 通过既有 SDD 会话完成初稿；Claude Code 独立复核时修正：

1. **Input 类型约束原本无效**：初稿通过空 `if/then` 检查 requirements/analysis type，实际不产生任何约束；改为 `requirementsArtifactRef` / `analysisArtifactRef` 的 `allOf + const`，并让 `existing_design` 限定为 design。
2. **Output `$defs.analysisData` 命名错误**：改为 `designContent` / `designData`，避免把 Design 数据误标为 Analysis。
3. **Output artifact 未限定类型**：初稿 artifacts 允许任意 artifactRef；改为仅 `type=design`，并验证 `ok` 至少一个 design Artifact。
4. **`state_model` 含有中文属性 `终态`**：改为规范字段 `terminal_states`。
5. **source refs 未绑定类型**：输出 schema 的 `source_requirements_ref`/`source_analysis_ref` 改为类型 const 的 artifactRef。
6. **Traceability 证据规则落后**：把 `resolution_evidence_refs` 更新为 F7 严格 SHA-256 规则（路径段/单摘要/绝对末尾）。
7. **`changelog: CHANGELOG.md` 指向不存在文件**：任务不允许新增 CHANGELOG；移除该引用。
8. **Envelope 字段和 Metadata 字段冲突**：任务书建议的 `skill_id`/`skill_version`/`warnings`/单数 `artifact` 与 `id/category/inputs/outputs/security/execution` 不在当前 P1-001 契约；按“以实际 Skill Standard 为准”未发明，报告明确记录。
9. **G2 混淆风险**：Schema 明确禁止 `needs_approval.gate_or_sa=G2`；未创建 GateDecision/Approval。
10. **条件字段与 L1 过度要求风险**：设计内容采用 Required/Conditional/Optional，coverage 支持 N/A/deferred；L1 不要求完整架构字段。
