# 系统架构设计

## 概述

SDD 采用六层架构设计，将软件研发能力分层解耦，确保核心能力与平台适配分离。

## 架构分层

```
┌─────────────────────────────────────────────────────────────┐
│                    L1 · 交互层 (UI)                         │
│         用户需求输入 / 任务确认 / 进度反馈 / 结果展示          │
└─────────────────────────────────────────────────────────────┘
                          ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│                L2 · 编排层 (Orchestration)                   │
│      任务识别 / 复杂度评估 / Skill路由 / 依赖管理 / HARD-GATE  │
└─────────────────────────────────────────────────────────────┘
                          ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│              L3 · 研发能力层 (Development Skills)             │
│  requirements-clarity / analysis / design / coding / review  │
│  testing / deployment / documentation / feedback-loop        │
└─────────────────────────────────────────────────────────────┘
                          ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│              L4 · 专业技术层 (Technical Skills)               │
│  Vue / React / TypeScript / Java / Spring Boot / Python /    │
│  SQL / RAG / Agent / Docker / Kubernetes / ...              │
└─────────────────────────────────────────────────────────────┘
                          ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│         L5 · 工程基础设施层 (Engineering Infrastructure)      │
│  Scripts / Templates / References / MCP / Git / 测试工具      │
└─────────────────────────────────────────────────────────────┘
                          ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│              L6 · 平台适配层 (Platform Adapter)               │
│  Codex / Claude Code / Cursor / Gemini CLI / OpenCode / ... │
└─────────────────────────────────────────────────────────────┘
```

## 各层职责

### L1 · 交互层

**职责：**
- 接收用户需求
- 展示执行进度
- 收集人工审批
- 呈现最终产物

**边界：**
- 不处理业务逻辑
- 不包含技术实现细节
- 与平台 UI 机制对接

### L2 · 编排层

**职责：**
- 任务类型识别
- 复杂度评估（L1/L2/L3）
- Skill 路由决策
- 依赖关系管理
- HARD-GATE 门禁控制
- 工作流执行跟踪

**关键组件：**
- `task-identifier` — 任务识别器
- `complexity-evaluator` — 复杂度评估器
- `skill-router` — Skill 路由器
- `gate-controller` — 门禁控制器
- `artifact-manager` — 产物管理器

### L3 · 研发能力层

**职责：**
- 提供独立的研发阶段能力
- 定义每个阶段的输入/输出契约
- 支持渐进式披露

**Skill 列表：**
| Skill | 输入 | 输出 |
|-------|------|------|
| requirements-clarity | 用户原始需求 | 需求文档 |
| analysis | 需求文档 | 分析报告 |
| design | 分析报告 | 设计文档 |
| coding | 设计文档 | 代码 |
| code-review | 代码 | Review 报告 |
| testing | 代码 + 测试用例 | 测试报告 |
| deployment | 代码 + 部署配置 | 部署产物 |
| documentation | 代码 + 设计 | 技术文档 |
| feedback-loop | 上线反馈 | 改进建议 |

### L4 · 专业技术层

**职责：**
- 提供特定技术栈的实现能力
- 被 L3 的 Coding 等 Skill 调用
- 保持技术无关性

**分类：**
- 前端：Vue / React / TypeScript / 性能优化
- 后端：Java / Spring Boot / Python / API 开发
- 数据库：MySQL / PostgreSQL / SQL 优化
- AI：Agent / RAG / Prompt Engineering / Workflow
- 工程：Git / 重构 / 依赖管理

### L5 · 工程基础设施层

**职责：**
- 提供通用工具和脚本
- 管理模板和参考文档
- 支持 MCP 集成
- 维护测试框架

**内容：**
- `scripts/` — 可执行脚本
- `templates/` — 标准模板
- `references/` — 参考文档
- `tools/` — 验证和质量检查工具

### L6 · 平台适配层

**职责：**
- 适配不同 Agent 平台的调用机制
- 管理平台特定的配置
- 维护兼容性矩阵

**平台支持：**
- Codex
- Claude Code
- Cursor
- Gemini CLI
- OpenCode
- OpenClaw

## 层间依赖关系

```
L1 → L2 → L3 → L4
              ↓
            L5 ← L6
```

**规则：**
- 上层可以调用下层
- 下层不能反向依赖上层
- L4 和 L5 之间双向依赖（技术 Skill 需要基础设施支持）
- L6 独立于其他层，通过配置适配

## 数据流

```
用户输入 → L1 接收 → L2 识别/路由 → L3 执行 Skill → L4 技术支持
    ↑                                                    ↓
    └──────── L5 基础设施 ←────────────────────────────── L6 平台适配
```

## 设计原则

1. **单一职责** — 每层只做一件事
2. **低耦合** — 层间通过明确接口交互
3. **高内聚** — 层内组件紧密协作
4. **渐进披露** — 按需加载资源
5. **可测试** — 每层可独立验证
6. **可扩展** — 新增平台或技术栈不影响核心
