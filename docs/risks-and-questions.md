# 风险与待确认事项

## 已识别风险

### 技术风险

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| 平台兼容性差异 | 中 | 部分功能无法移植 | P7 阶段专项验证，必要时降级支持 |
| 子 Agent 协作不稳定 | 中 | 并行执行可能失败 | 设置超时和重试机制，提供降级方案 |
| Skill 触发不准确 | 低 | 效率下降 | 持续优化 description，使用 eval 验证 |
| 产物管理冲突 | 低 | 数据丢失风险 | 原子写入，冲突检测，版本控制 |

### 项目风险

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| 范围蔓延 | 高 | 进度延误 | 严格遵循 P0-P7 阶段划分，变更需评审 |
| 复杂度评估不足 | 中 | 返工 | P0 阶段充分调研，预留缓冲时间 |
| 跨团队协作困难 | 低 | 沟通成本 | 明确接口契约，文档先行 |

### 兼容风险

| 平台 | 已知限制 | 验证状态 |
|------|----------|----------|
| Codex | 子 Agent 不支持 | 待验证 |
| Cursor | 自动触发机制不同 | 待验证 |
| Gemini CLI | 无内置 Skill 支持 | 待验证 |
| OpenCode | 生态较新 | 待验证 |

## 需要用户决策的问题

### 架构决策

1. **编排引擎的实现方式**
   - A: 在 orchestration Skill 中硬编码
   - B: 使用声明式 YAML 配置
   - C: AI 动态生成执行计划
   - **当前倾向：** B（声明式）

2. **专业技术 Skill 的范围**
   - A: 只包含主流技术栈（Vue、React、Java、Python）
   - B: 包含更多细分领域（Rust、Go、Swift 等）
   - C: 按需创建，不预设范围
   - **当前倾向：** A + C

3. **部署 Skill 的支持范围**
   - A: 只支持容器化部署（Docker）
   - B: 支持 Docker + K8s + 至少一种云服务商
   - C: 全部支持，包括传统服务器
   - **当前倾向：** B

### 项目决策

4. **P0 阶段是否需要产出可直接运行的 Demo？**
   - 是：增加工作量，但可验证架构
   - 否：专注设计，后续再验证
   - **建议：** 否，P0 专注设计

5. **是否需要立即发布到 ClawHub？**
   - 是：可获得社区反馈
   - 否：先内部测试，成熟后再发布
   - **建议：** 否，P7 完成后发布

6. **是否支持私有化部署？**
   - 是：需要额外的安装和配置机制
   - 否：仅支持在线使用
   - **待定**

## 边界问题

以下问题需要在后续阶段明确：

1. **SDD 的定位**
   - 是独立项目还是 OpenClaw 的插件？
   - 还是两者兼有？

2. **与其他 Skill 体系的关系**
   - 是否与现有 OpenClaw skills 共存？
   - 还是替换部分现有功能？

3. **维护模式**
   - 单人维护还是团队协作？
   - 是否有贡献者准入机制？
