# 风险与待确认事项

## 已识别风险

### 技术风险

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| 平台兼容性差异 | 中 | 部分功能无法移植 | P7 阶段专项验证，必要时降级支持 |
| 子 Agent 协作不稳定 | 中 | 并行执行可能失败 | 设置超时和重试机制，提供降级方案 |
| Skill 触发不准确 | 低 | 效率下降 | 持续优化 description，使用 eval 验证 |
| 产物管理冲突 | 低 | 数据丢失风险 | 原子写入，冲突检测，版本控制 |

### 项目风险

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|----------|
| 范围蔓延 | 高 | 进度延误 | 严格遵循 P0-P7 阶段划分，变更需评审 |
| 复杂度评估不足 | 中 | 返工 | P0 阶段充分调研，预留缓冲时间 |
| 跨团队协作困难 | 低 | 沟通成本 | 明确接口契约，文档先行 |

### 兼容风险

| 平台 | 已知限制 | 验证状态 |
|------|----------|----------|
| Codex | 子 Agent 预期不支持；工作流需适配 | 设计假设，未实测 |
| Claude Code | 子 Agent/Workflow 映射需适配 | 设计假设，未实测 |
| Cursor | 自动触发/子 Agent 预期不支持 | 设计假设，未实测 |
| Gemini CLI | 无内置 Skill 支持；审批机制缺失 | 设计假设，未实测 |
| OpenCode | 生态较新，能力不确定 | 设计假设，未实测 |
| OpenClaw | SDD Skill/Workflow/审批未验证；仅 CLI 会话能力有证据 | 部分验证（仅 CLI），SDD 能力待验证 |

> 平台能力矩阵与证据范围见 [platform-architecture.md](architecture/platform-architecture.md) 与 [ADR-004](decisions/ADR-004-cross-platform.md)。未实测能力不得写成已支持或完全兼容。

## 需要用户决策的问题

### 架构决策

1. **编排引擎的实现方式**
   - A: 在 orchestration Skill 中硬编码
   - B: 使用声明式 YAML 配置
   - C: AI 动态生成执行计划
   - **当前倾向：** B（声明式）

2. **专业技术 Skill 的范围**
   - A: 只包含主流技术栈（Vue、React、Java、Python）
   - B: 包含更多细分领域（Rust、Go、Swift 等）
   - C: 按需创建，不预设范围
   - **当前倾向：** A + C

3. **部署 Skill 的支持范围**
   - A: 只支持容器化部署（Docker）
   - B: 支持 Docker + K8s + 至少一种云服务商
   - C: 全部支持，包括传统服务器
   - **当前倾向：** B

### 项目决策

4. **P0 阶段是否需要产出可直接运行的 Demo？**
   - 是：增加工作量，但可验证架构
   - 否：专注设计，后续再验证
   - **建议：** 否，P0 专注设计

5. **是否需要立即发布到 ClawHub？**
   - 是：可获得社区反馈
   - 否：先内部测试，成熟后再发布
   - **建议：** 否，P7 完成后发布

6. **是否支持私有化部署？**
   - 是：需要额外的安装和配置机制
   - 否：仅支持在线使用
   - **待定**

## 边界问题

以下问题需要在后续阶段明确：

1. **SDD 的定位**
   - 是独立项目还是 OpenClaw 的插件？
   - 还是两者兼有？

2. **与其他 Skill 体系的关系**
   - 是否与现有 OpenClaw skills 共存？

3. **维护模式**
   - 单人维护还是团队协作？

## P0-002 已收敛事项

以下架构一致性问题已在 P0-002 收敛，不再作为开放风险：

- 六个核心概念与职责边界（Agent / Orchestration / Workflow / Skill / Tool / Platform Adapter）
- G1–G6 门禁的统一定义、失败回退与审计（ADR-006）
- 通用 Skill 规范与平台元数据的分离
- Workflow DAG：Review/Testing 并行、双门禁、部署依赖
- 权限（R0–R4）与审批控制的分离与风险矩阵
- 六平台清单统一（含 OpenClaw）与未验证声明
- Task Context / Artifact 的字段、归属、版本、并发与归档

仍待后续阶段解决：沙箱/权限运行时、Workflow Schema、编排引擎、跨平台实测、安全测试。
