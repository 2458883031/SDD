# ADR-001：总体架构与分层设计

**状态：** 已采纳  
**日期：** 2026-11-20  
**决策者：** SDD 项目架构组

## 背景

构建一套完整的软件研发 Skill 体系时，面临两种架构选择：
1. **单体架构** — 所有逻辑塞进少数几个大 Skill
2. **分层架构** — 按职责分层，每层专注特定问题

## 问题

如何设计架构以支持：
- 完整的软件研发生命周期
- 多种技术栈和平台
- 动态流程编排
- 独立模块复用
- 可扩展和可维护

## 候选方案

### 方案 A：扁平 Skill 集合

将所有 Skill 平铺在 `skills/` 目录下：
```
skills/
  brainstorming.md
  planning.md
  coding.md
  testing.md
  ...
```

**优点：**
- 简单直观
- 易于理解

**缺点：**
- 职责不清
- 难以复用
- 扩展性差

### 方案 B：领域分组

按研发阶段分组：
```
skills/
  requirements/
    clarity.md
    gathering.md
  development/
    coding.md
    review.md
  deployment/
    ci-cd.md
    manual.md
```

**优点：**
- 有一定组织性
- 同阶段 Skill 集中

**缺点：**
- 跨阶段协作困难
- 缺少统一编排机制
- 平台适配混乱

### 方案 C：六层架构（选定）

```
L1 · 交互层
L2 · 编排层
L3 · 研发能力层
L4 · 专业技术层
L5 · 工程基础设施层
L6 · 平台适配层
```

**优点：**
- 职责清晰
- 层次解耦
- 可扩展性强
- 平台适配独立

**缺点：**
- 设计复杂度较高
- 需要严格遵循分层原则

## 决策

采用**方案 C：六层架构**。

核心设计原则：
1. **核心能力与平台适配解耦**
2. **Skill 模块职责单一**
3. **支持渐进式披露**
4. **支持动态 Skill 路由**
5. **支持任务依赖和工作流编排**
6. **支持 HARD-GATE 人工审批**

## 理由

1. **复杂性管理** — 六层架构将复杂系统分解为可管理的层次
2. **复用性** — 每层可独立复用，如 L4 技术 Skill 可被多个 L3 Skill 调用
3. **可维护性** — 修改某一层不影响其他层
4. **跨平台** — L6 平台适配层隔离了不同 Agent 平台的差异
5. **质量保障** — L2 编排层提供统一的门禁和质量控制

## 优缺点

### 优点
- 清晰的职责边界
- 易于新增技术栈或平台
- 支持渐进式开发（P0-P7 分阶段实施）
- 独立的测试和验证

### 缺点
- 初期设计成本高
- 需要严格的架构纪律
- 层次间通信需要精心设计

## 后续影响

1. **P1** — 制定详细的 Skill 规范和 Schema
2. **P2** — 实现编排引擎核心
3. **P3-P6** — 逐步实现各层 Skill
4. **P7** — 跨平台集成测试
